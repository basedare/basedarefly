# BaseDare engineering and learning harness

Start with the existing [Product Constitution](../brain-vault/00-control/product-constitution.md), [architecture](../docs/architecture.md), [financial canon](../docs/FINANCIAL_CANON.md), [Brain memory rules](../docs/basedare-brain-memory-schema.md) and [sprint audit](../docs/design/irl-growth-harness-2026-11-08.md). These remain authoritative; this is not a new agent service or runtime product graph.

## Operate

1. `npm run graphify:rebuild` after source edits. `npm run harness:check` runs the deterministic harness evaluations and checks required sources, duplicate nodes and dangling edges in the actual Graphify code graph. Existing CI still owns build, safety, auth, discovery, participation, review, social, business and migration regressions. This does not replace their checks.
2. `npm run harness:evaluate -- --suite qr --out /tmp/basedare-qr-evaluation-UNIQUE.json` runs the actual disposable PostgreSQL/handler journey and existing privacy tests. Other allowlisted suites: discovery, social, business, safety, all. Commands come from `scenarios.json`, run without a shell, have a ten-minute ceiling per command, stop on failure and retain private temporary logs. Production/provider environment variables are not inherited. This is an allowlist, **not an OS security sandbox**: run untrusted contributions in existing CI, not against founder credentials.
3. In the existing creator-attribution admin screen, select a bounded window and **Export aggregate harness evidence**. It covers authored free-adventure QR cohorts only and contains only source/window/unit/completeness and six counts. Other destination types have N/A participation stages, not zero conversions. No identities, emails, raw events, exact coordinates or venue/creator roster. Source overflow exports unknown counts. The declared source is not a cryptographic attestation; the founder reviews provenance. Entries and stage events remain browser-journey/target observations, not unique people.
4. `npm run harness:evaluate -- --observation /path/to/approved-export.json --out /tmp/basedare-plan-UNIQUE.json` validates the aggregate input and generates deterministic hypotheses. Without an export, product evidence is explicitly unavailable and the planner requests evidence; it does not diagnose a broken funnel. An incomplete real export is handled separately. The example fixture is labelled synthetic. Plans do not claim measured lift or start experiments.
5. Choose one proposal, inspect the code graph and real source, use a named branch, preserve invariants and run relevant registered evaluations. Open a **draft PR** with the hypothesis, exact revision, evidence provenance, before/after behavior, test receipts, remaining gates and rollback. The current QR sprint is the first example of this workflow; the harness does not invoke an autonomous Codex runtime.
6. A reviewer other than the implementing agent reviews the diff and receipts. CI is an independent mechanical gate, not a substitute for that reviewer. The founder approves merge/deploy. Only then compare matched windows/channels/device conditions and record the result in `learning/journal.md`, using the experiment template. Small samples, bots, consent, missing renders and frozen attribution prevent causal claims.

Reports must be new `.json` files outside the application source tree; existing files are never overwritten. Review and copy only sanitized observations/decisions into version control. No secrets or raw customer records belong in the harness.

## Current scope and controls

- Observe: existing tests, code graph and explicitly exported aggregate QR signals.
- Diagnose: bounded source/stage checks, small-sample caution and prioritized proposals with scope, cost, expected impact and success criteria.
- Implement: a human/Codex collaborator uses existing tools on an isolated branch. No recursive self-modification or automatic commits, PR creation, merges, deploys, sending, contracts or money movement.
- Evaluate: meaningful existing suites plus harness negative controls; local canonical destination tests detect unavailable hosts, revoked/transferred identities and cancelled/expired sources. Tombstones are retained and never automatically repaired/deleted. No runtime graph database or automatic production DB access.
- Learn: version-controlled hypotheses and verified engineering findings; actual product outcomes stay NOT MEASURED until field evidence exists.

There is no scheduled autonomous worker, new telemetry collector, extra model service, production credential, payment authority or new login provider. Founder approval remains mandatory for production. Real-phone, provider, moderation, consent, withdrawal and financial gates remain intact.

Later autonomy requires trustworthy real telemetry, consented field use, a named independent reviewer and explicit founder controls. First prove one real QR → useful guest action → voluntary invitation → returning participant loop.
