# Buyer workspace and quality automation

The buyer workspace repeated state, hid useful actions among decorative panels and treated some planned or approved records as funding/payment. Owner APIs also accepted insufficient authority. This increment simplifies the existing workspace and closes those access gaps without replacing business onboarding or the financial lifecycle.

## Result

- Returning buyers see Your work, New request, one overview and concise briefs. Each brief shows one current state and next step. Details & responses retains evidence, history, local shortlist, place context and advanced tools. Phone layouts stack titles/badges and budget fields; controls retain44px targets.
- Account verification protects buyer profile, campaign, response and matching reads with private/no-store responses. Unknown accounts cannot list other buyers' work. Existing wallet/session infrastructure is reused, with purpose-specific buyer signatures and visible retry. Creator discovery forwards current session authority and refreshes when sign-in finishes.
- Funding/payment totals require non-simulated recorded transaction references. An approved submission is not reported as paid. An example receipt is never labelled a buyer's result. These are database references, not a fresh chain receipt verification.
- Dormant legacy CREATOR slot mutation endpoints return410 and leave scores, reputation, evidence and notifications unchanged. Historical reads remain owner-scoped. Canonical PLACE missions keep their existing participation, proof, review, funding and payment protections.
- No dependency, migration, auth provider, live campaign, email, media provider, production fixture or money movement is added. Public business nodes/Matrix, guest enquiries and the existing financial canon remain.

## Useful automation now

The offline harness chooses reviewed, registered tests from actual changed source files. It deduplicates suites, fails on unmapped runtime source, records exact revision/source fingerprints and preserves exit/signal/timeout evidence. Git filenames are read as NUL-separated paths so Unicode or line breaks cannot escape checks. Source changes during a run invalidate its result.

CI plans checks from the real comparison base, executes buyer privacy/database regression and preserves seven-day quality evidence alongside existing gates. CODE_GRAPH_ONLY, PLAN_ONLY and REGISTERED_SCENARIOS are explicit. A graph-only result never claims journey acceptance; releaseReady remains false. Fixed test commands run without inherited production/provider credentials and stop after failure. This is an allowlist, not an OS isolation boundary for untrusted code.

The improvement loop remains: inspect reviewed aggregate evidence → choose a bounded hypothesis → change on a branch → run affected checks → independent review → exact CI/release verification → compare real field evidence. Missing telemetry remains unknown. No automatic patching, outreach, PR submission, merge, deployment or product-lift claim is enabled.

## Evidence and limits

Local actual-handler/disposable-PostgreSQL tests exercise EOA signature authority, privacy, unknown buyers, genuine signed registration, creator reads, parked writes and unchanged database/notification records. External contract verification is replaced with local cryptographic verification; OAuth is request-fixtured. These tests do not prove a real smart-wallet RPC, payment, media, OAuth recovery or physical-device journey.

The 18 harness checks include actual child-process negative controls: failure exit 7 stops the next check, synthetic provider credentials are absent, and a successful test that changes source invalidates the receipt. Funding/payment presentation and existing business policy tests pass. Full lint has zero errors with existing warnings; optimized build/typechecking pass. Native disclosures and no-overflow layouts were checked at 320px, 390px and desktop using an explicitly synthetic SSR fixture. Buttons requiring hydration are not claimed as tested by that fixture.

Independent review identified and confirmed repairs for session-aware map reads and quoted Git filenames. The reviewer independently ran the two focused path/runner canaries, 2/2 passing. Exact-head hosted CI, merge, production status, public/private read-only checks and screenshots belong in the release receipt after they occur. Normal Preview has no isolated application database and must not be described as full hosted acceptance.

The final change-aware local run executed all 14 deduplicated registered checks selected by the actual diff: buyer policy/database, business policy/database, discovery/usability/identity, discovery intelligence, social database/Moments, harness, static safety, refund safety and redirect security. All passed, source fingerprints stayed unchanged and no runtime files were unmapped. The report correctly retained releaseReady:false pending separate review/release acceptance. Graphify rebuilt to 4,569 nodes and 5,512 edges across 1,330 source files; these counts describe code only.

Remaining paid/provider/phone/operating gates in the launch handoff remain open. This release improves engineering evidence and buyer safety; it does not make the entire business launch 100% proven.
